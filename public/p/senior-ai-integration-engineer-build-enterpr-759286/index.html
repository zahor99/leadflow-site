LangGraph multi-agent platform, phased to production

Senior AI Integration Engineer Build Enterprise AI Automation & Workflow Platform

In short

Gergely proposes a modular, LangGraph-orchestrated multi-agent platform covering support, sales, research, and ops — with RAG, Redis short-term memory, Postgres audit logs, and human-approval checkpoints built into the graph from day one. Delivery is phased: orchestrator plus two or three core agents ship first, so the client holds a running system before the full ecosystem is built out. Rate is $95/hr.

Architecture I'd propose

  • Event / Webhook — n8n external triggers
  • LangGraph Orchestrator — state graph + routing
  • Agent Pool — support, sales, research, ops
  • MCP Tool Layer — shared tools, no coupling
  • Memory & Knowledge — Redis + pgvector + Postgres
  • Human Approval Gate — graph checkpoint, auditable
Assumes: Assumes external triggers arrive via webhook; adjust if event bus (Kafka/RabbitMQ) is already in place · Assumes pgvector sufficient for initial RAG; Qdrant swap-in if scale demands it · Assumes AWS or GCP for deployment; Docker throughout — tell me where I'm wrong and the design adapts.

Plan

  • Phase 1 – Core platform (Week 1-3) — Orchestrator + support & sales agents, RAG, approval gates live
  • Phase 2 – Agent expansion (Week 4-6) — Research, doc processing, analytics agents added
  • Phase 3 – Observability (Week 7-8) — Prometheus/Grafana, retry/dead-letter, full docs
