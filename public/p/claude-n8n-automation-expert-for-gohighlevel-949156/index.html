Architecture I'd propose

  • GoHighLevel CRM — pipelines, tags, custom fields
  • GHL Webhook OUT — POSTs contact data on trigger
  • FastAPI Endpoint — receives payload, runs logic
  • Claude API — tool-use + structured output
  • n8n Orchestration — routing, retries, side effects
  • GHL Write-back — result → internal API → CRM
Assumes: Assumes GHL sub-account needs building or reconfiguring from your current state · Assumes Claude tool-use / structured output for AI reasoning steps · Assumes n8n self-hosted or cloud for orchestration outside GHL · Assumes FastAPI webhook surface for logic GHL native workflows cannot handle — tell me where I'm wrong and the design adapts.

Plan

  • Phase 1 - GHL Foundation (Week 1-2) — Configured sub-account: fields, pipelines, tags, core workflows
  • Phase 2 - Claude AI Layer (Week 3-4) — FastAPI webhook + Claude scoring live in your GHL flows
  • Phase 3 - Edge-case Hardening (Week 5) — Error handling, retries, Loom docs, annotated flow diagrams
