Proposal walkthrough

Two RAG agents for packaging sales and staff

AI Agent Development

In short

A customer-facing sales agent and an internal staff assistant, both built on a shared RAG core over your product catalog, pricing rules, and process docs. The customer agent calculates live quotes via structured tool calls; the staff agent drafts emails and surfaces ops docs in seconds. Delivered in two phases — Agent 1 live and revenue-facing before Agent 2 is built.

Architecture I'd propose

  • Your documents — catalog, pricing, process docs
  • Ingestion pipeline — chunk, tag, embed
  • pgvector store — retrieval + reranker
  • Pricing tool calls — structured, deterministic
  • Agent 1 — Customer — website chat, live quotes
  • Agent 2 — Staff — web UI or Slack
Assumes: Assumes docs are PDFs or structured files — Confluence or SharePoint changes the ingestion node, nothing else · Assumes Claude or OpenAI API as the LLM — swappable without redesigning the retrieval layer · Assumes Agent 2 in a web UI first; Slack integration is additive in Phase 3 — tell me where I'm wrong and the design adapts.

Plan

  • Phase 1 - Customer agent (Week 1-3) — Live website agent with accurate answers and dynamic quotes
  • Phase 2 - Staff assistant (Week 4-5) — Internal agent on shared knowledge base
  • Phase 3 - Expand & monitor (Week 6+) — Eval runs, doc-update workflow, optional Slack
