Multi-model AIGC pipeline with built-in eval layer

AI-Driven Content Production Engineer

In short

Gergely proposes a modular, multi-model content production pipeline — Claude/OpenAI/Gemini for reasoning and copy, Flux/ComfyUI for image and video generation — orchestrated in Python/FastAPI with structured outputs and schema validation at every boundary. QA is engineered in from day one: eval harnesses, golden-set scoring, and downstream feedback loops gate every promotion to production. The pipeline is designed so individual generation steps swap out as better models emerge, protecting your investment as the AIGC landscape moves.

Architecture I'd propose

  • Content Brief — structured input schema
  • Reasoning Layer — Claude / OpenAI / Gemini
  • Image & Video Gen — Flux + ComfyUI nodes
  • Orchestration — Python / FastAPI + retries
  • Eval Harness — SSIM / embedding / LLM-judge
  • Publish / Output — downstream platform
Assumes: Assumes output targets are image and/or video assets plus written copy · Assumes a downstream publish endpoint or platform API exists · Assumes model selection will be benchmarked on your actual data before commit — tell me where I'm wrong and the design adapts.

Plan

  • Phase 1 - Core pipeline (Week 1-2) — End-to-end brief-to-output flow, live and runnable
  • Phase 2 - Eval layer (Week 3) — Harnesses, golden set, drift detection in Postgres
  • Phase 3 - Observability (Week 4) — Cost, latency, quality metrics logged centrally
