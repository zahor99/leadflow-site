Proposal walkthrough

Status-driven Make content engine, zero duplicates

Build a Make.com Content Engine: Google Sheets + Claude API + Social Auto-Posting

In short

A six-scenario Make.com pipeline that turns a Google Sheets content plan into scheduled posts across LinkedIn, Facebook, Instagram, Threads, and X — with Claude generating copy, a human approving in the sheet, and strict idempotency guaranteeing no post ever publishes twice. Phase 1 delivers a fully working system for three LinkedIn pages and one Facebook Page in two to three weeks. Handover documentation and 30 days of support are included.

Architecture I'd propose

  • Google Sheets — Source of truth + config
  • Copy Generator — Pulls 'To Generate' rows → Claude API → JSON back to sheet
  • Media Watcher — Drive folder → public URL → R2 re-host
  • Pre-flight Validator — Date, char limit, media present
  • Publisher — Router → LinkedIn / Meta / aggregator
  • Monitor & Cleanup — Locks, token expiry, error log
Assumes: Cloudflare R2 or equivalent S3 bucket available for media re-hosting · Aggregator selection (Blotato / Publer / Buffer) finalised in Phase 0 · Meta and LinkedIn admin access granted before Phase 1 start · 13-state model implemented with Pending / In-Flight / Terminal grouping per design flag in proposal — tell me where I'm wrong and the design adapts.

Plan

  • Phase 1 — MVP (Week 1–3) — Sheets, Drive, scenarios 1–4, 3 LinkedIn + 1 Facebook Page live
  • Phase 2 — Full coverage (Week 4–5) — Instagram, Threads, X, monitoring, weekly reporting
