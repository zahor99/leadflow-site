Self-hosted AI voice agent for inbound oil delivery calls

AI Voice Agent Developer — Twilio + OpenAI Realtime API + Authorize.net (Service/Delivery Business)

In short

Gergely proposes a self-hosted Python/FastAPI + Twilio Media Streams + OpenAI Realtime API voice agent for your heating oil, estimate, and service-call flows — no per-minute platforms, code you own. The proof-of-concept delivers one live Twilio number with intent routing, pricing lookup, and Google Sheets logging in two weeks. Full build adds DTMF payment capture via Authorize.net, calendar scheduling, and an overbooking kill-switch you can toggle yourself.

Architecture I'd propose

  • Twilio Media Stream — WebSocket audio in/out
  • FastAPI Server — Python, self-hosted
  • OpenAI Realtime API — intent + conversation
  • DTMF Payment Path — Gather → Authorize.net
  • Calendar + Kill-switch — Google Cal / Supabase flag
  • Google Sheets Logger — every call outcome logged
Assumes: Assumes pricing tables are queryable as structured data (CSV, Sheet, or JSON endpoint) · Assumes Google Calendar is your scheduling source of truth · Assumes Optimum Online numbers forward into Twilio PSTN · Assumes self-hosted means a cloud VM or container you control — tell me where I'm wrong and the design adapts.

Plan

  • Phase 1 — POC (Week 1–2) — One live Twilio number: intent routing, pricing, Sheets log
  • Phase 2 — Payments + Scheduling (Week 3–4) — DTMF payment, calendar booking, kill-switch
  • Phase 3 — Full Rollout (Week 5+) — All numbers live, Optimum forwarding, full logging
