Entity resolution, ranking, and signal extraction pipeline

AI Engineer / Machine Learning

In short

Gergely proposes a tiered intelligence pipeline: Apify crawlers ingesting fragmented web sources, an LLM extraction layer normalising entities, and a scoring + LLM-judge step that surfaces the five signals most likely to matter — with evals built in from day one. The architecture is modular so new source classes can be added without rewiring the ranking layer. Rate is $75/hr.

Architecture I'd propose

  • Apify Crawlers — filings, news, LinkedIn, jobs
  • LLM Extraction — typed schemas, normalised entities
  • Entity Resolution — fuzzy + embedding similarity
  • Scoring Layer — recency × authority × materiality
  • LLM Judge — state change, finance, leadership
Assumes: Assumes source classes start with filings, news, LinkedIn, job postings — others can be added modularly · Assumes materiality profiles are defined per company and iterated with evals on a labelled holdout · Assumes async, retryable ingestion with dead-letter queues for messy web data — tell me where I'm wrong and the design adapts.

Plan

  • Phase 1 — Core pipeline (Week 1-2) — Working crawl → extract → score loop on one source class
  • Phase 2 — Entity resolution + evals (Week 3-4) — Dedup, LLM judge, eval harness, precision/recall baseline
  • Phase 3 — Full source coverage (Week 5+) — All source classes live, modular ranking layer
